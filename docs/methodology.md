# 综合日榜 · v1.3

综合榜使用公开排名构建热度指数，不表示播放量或市场份额。日内展示最新有效快照，跨日保留北京时间当日最后一次有效快照；日内结果是动态观察，不承诺所有平台已发布当日榜期。

## 计分

所有平台统一以前 **50 名**参与计算，其余原榜记录保留展示、计分为零。名次 `r` 的基础分：

```text
P(r) = 0.9 × exp(−(r−1)/25) + 0.1    （1 ≤ r ≤ 50）
S(song) = 100 × Σ 有效平台权重 × P(r)
```

| 平台 | 基础权重 |
| --- | ---: |
| QQ 音乐 | 25% |
| 酷狗音乐 | 20% |
| 酷我音乐 | 5% |
| 网易云音乐 | 30% |
| Apple Music | 10% |
| 汽水音乐 | 10% |

有效权重为平台基础权重除以本次有效平台基础权重之和。QQ、酷狗、酷我属于同一来源组；与网易云、Apple、汽水合计四个独立组，至少两个组可用才发布。

来源须达到采集深度及新鲜度要求：汽水 50 首、9 天，其余平台 100 首、48 小时；源时间未知时明确标注。v1.3 保持 v1.2 的评分公式与权重，增加有期限的最近成功观察沿用：本次采集失败时，使用仍在观察年龄、源榜期两个窗口内的完整成功记录，保留原来源时刻，标记 `stale`。当日早前成功 run 也可沿用，不用过期、未来、示例或事后回填数据；具体规则见[数据来源](sources.md)。

`ok` 与 `stale` 都属于可计分平台；`coverage.available = fresh + cached`。`complete` 表示全部来源可计分，不代表全部来源本次成功，必须同时披露 `cached`。只有没有合格历史观察的失败来源才退出有效来源集合，其他有效权重随之归一化。缺少平台显示部分覆盖；不足发布门槛时保留最近有效榜，同时展示本轮采集状态。

综合榜发布有正分的前 100 首，按未舍入总分排序；同分依次按参与计分的平台数降序、稳定歌曲 ID 升序。原榜涨跌和 MV 关联不参与计分。每日多次采样不重复累计票数。

## 歌曲身份

自动归一化使用 Unicode NFKC、大小写及空白规则，以完整曲名和排序后的完整艺人集合合并。保留 Live、Remix、伴奏等版本标签，人工确认的映射保存在 `config/aliases.json`。同一录音在同一平台出现多次时只取最好名次。

`appearances` 统计保留原榜中的平台数，`scoringAppearances` 统计计分窗口内的平台数；`platforms[].eligible` 标记是否参与计分。

## 涨跌与历史

仅在前一个自然日存在，且模式、有效来源集合、方法版本和歌曲映射签名相同时比较日榜：

```text
delta = 昨日名次 − 今日名次
```

正数上升，负数下降；可比较但昨日 Top 100 无此曲时标记新入榜，不可比较时标记未知。综合日榜变化写入 `combinedMovement`，平台相对上期变化写入 `sourceMovement`。沿用不改变有效来源集合；同一方法下，含沿用数据的日榜仍能比较，`coverage.comparisonUsesCache` 明确标注本日或对照日含历史沿用。比较反映已发布日榜的变化，不表示所有平台刚刚更新；原榜涨跌及观察日期继续保留原值。方法升级与缺源导致的签名变化仍禁止直接比较。

平台涨跌优先采用官方提供的已确认变化，包括持平与新入榜。官方未提供或方向未知时，按平台曲目 ID 对比昨日最后一期同平台完整快照，补充 `origin: snapshot-comparison`、`period: previous-day`，并保留官方原值 `raw`。该比较独立于综合榜覆盖与歌曲映射；平台榜单身份与采集深度必须一致，双方实际观察日期必须分别为今日、昨日。早于昨日的缓存不当作昨日新观察。昨日采集范围内无此曲时，只表示“新入采集范围”，不代表平台首次上榜，也不假定昨日为第 101 名。

综合涨跌榜按日榜名次变化幅度分别排列上升、下降，新入榜单列，见[涨跌榜方法](movement.md)。固定发榜时刻未确认时不作猜测；[更新频率观察](sources.md#更新频率观察)按保存的歌曲 ID 与名次变化给出实际发生区间。

历史记录保存各自方法版本，缺失日不补零、不插值。`npm run recompute` 可从已发布日榜的完整来源记录重算；独立回填的平台历史原榜不参与综合计分。构建网站时也可用已保存的相邻日快照补充平台变化展示，不改写 `data/` 原始归档、分数或比较签名。周、月汇总见[周榜方法](weekly.md)、[月榜方法](monthly.md)。
