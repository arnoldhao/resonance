# 共振综合榜 · 方法论 v1.1

2026-10-23 起接入汽水官方 Top 50 周榜，所有平台统一用前 50 名计分；QQ、网易云、酷狗、酷我和 Apple 原榜仍保留前 100。2026-10-22 的历史版本 1.0 保留原先前 100 的计算口径，不自动改写，两版之间不显示涨跌。

这是一个基于公开排名的跨平台热度指数，不是播放次数、市场份额或“官方全国榜”。它回答：**哪些录音在多个平台同时处于显著位置？** 权重和曲线参数都是公开、可修改的编辑选择。

## 1. 对齐观察单位

采集保留 QQ、网易云、酷狗、酷我、Apple 前 100 个连续名次，以及汽水完整前 50 名。各来源必须达到自己的完整性门槛；汽水官方榜本身只有 50 首，不能误判为截断，也不能伪补成 100 首。

综合计算统一采用所有平台可观察到的前 50 名，51–100 名仍可在平台原榜和 API 查看，贡献为 0。这避免因平台榜长不同，将汽水不可见的第 51–100 名与别家的可见名次直接比较。各平台统计窗口和受众仍不同，原始热度数字不可相加。汽水是周榜，日快照不改变其周统计口径。

每天三次取样，日榜是北京时间当日最后一次满足发布门槛的快照，没有对三个时点重复累计投票。源榜未更新时同一期次再次出现是正常情况；采集时间不冒充平台更新时间。

## 2. 名次换算

对平台 p 的名次 r（1–50）：

`P(r) = 0.9 × exp(−(r−1)/25) + 0.1`

未进入该平台前 50：`P = 0`。

| 名次 | 平台基础分（×100） |
| --- | ---: |
| 1 | 100.00 |
| 10 | 72.79 |
| 25 | 44.46 |
| 50 | 22.68 |
| 51–100 | 0（仅保留原榜展示） |

指数部分突出靠前排名，而 10% 的入榜底分使跨平台的稳定出现有意义。它不是平台原始热度，也不是概率。不额外奖励涨幅，避免新歌被重复加权后把综合热度榜变成飙升榜。

## 3. 来源权重与相关性

原始组权重：腾讯音乐 40%、网易云 30%、Apple 20%、汽水 10%。腾讯音乐组三个平台的用户与曲库相关，健康平台均分 40% 的组内权重。这个处理降低重复计票，但并不声称已经统计消除了相关性。

仅对本次成功、数据完整且满足新鲜度要求的来源计分。有效组权重归一化至 100%，组内再均分。例如汽水未接入、其余五源成功时：腾讯音乐组 44.44%，网易云 33.33%，Apple 22.22%；QQ/酷狗/酷我各 14.81%。

`S(song) = 100 × Σ 有效平台权重 w(p) × P(r(song,p))`

所有平台第一时总分为 100；只在一个平台出现仍有机会进入综合榜，但它只能获得该平台对应权重的分数。站点展示每个平台的基础分及加权贡献。排序使用未四舍五入的原始总分；相同总分时优先参与计分的平台覆盖数，再用稳定歌曲 ID 排序，不用随机数。综合榜发布有正分的前 100 名；各平台原榜保留自己的采集深度，不会随综合榜截断。

`appearances` 统计所有已采原榜上的出现次数；`scoringAppearances` 仅统计前 50 内的出现次数。歌曲 `platforms[].eligible` 标记是否处于计分窗口，超过窗口的原榜名次仍显示，`score` 与 `contribution` 均为 0。

## 4. 发布质量

- 至少两个独立来源组才发布。QQ + 酷狗 + 酷我仍只算一个组。
- 缺任何目标平台，都展示“部分覆盖”；不能把四平台成功写成六平台完整上线。
- 其他五源保留 48 小时新鲜度窗口；汽水官方周榜使用 9 天（一个周期加两天宽限），不能用日榜的 48 小时门槛误判正常周榜。只有日期或无时区期次时按日历日期比较，不猜测实际时区或发布时刻。超过各自窗口暂停计分；源时间未知时显式保留空值，此时无法保证榜单新鲜度。
- 本轮失败的来源移出本轮分母，不把昨日数据补作今天的成功来源。不足发布门槛时保留最近有效榜，但站点同时展示本轮失败状态和旧榜日期。
- 平台明确错误会记录到状态和 Actions Summary；不自动重试、也不换成第三方代理或其他榜单。

## 5. 跨平台歌曲身份

自动合并只做 Unicode NFKC、大小写/空白归一，再使用“完整曲名 + 排序后的完整艺人集合”。保留 Live、伴奏、Remix、翻唱等版本标签；不使用模糊匹配把不同录音强行合并。相同名字的不同艺人保持独立。

这是一条保守规则，仍可能把同名艺人的不同录音合并，或因为繁简体、合作艺人表示方式、曲名副标题而漏合并。初版不做无证据的繁简/译名/录音自动推断，用 `config/aliases.json` 显式纠正。

```json
{
  "artists": { "Jay Chou": "周杰伦" },
  "tracks": {
    "qq:真实歌曲MID": {
      "id": "recording-curated-001",
      "title": "确认后的曲名",
      "artists": ["确认后的艺人"]
    },
    "apple:真实歌曲ID": {
      "id": "recording-curated-001",
      "title": "确认后的曲名",
      "artists": ["确认后的艺人"]
    }
  }
}
```

同一个稳定 ID 表示人工确认同一录音；拆分则给不同 ID。一个录音在同平台多次出现时只计最好名次的一票，但原始来源行全部保留。Apple 的组合艺人字符串不会按逗号随意拆分；必要时通过曲目映射纠正。

## 6. 涨跌与历史

只有前一个北京时间自然日存在、模式相同、健康来源集合相同、公式版本相同、歌曲映射签名相同，才展示 `昨日名次 − 今日名次`。第一次出现没有昨日名次，显示“新入榜”或“—”；整个口径不可比时统一用“—”，不把它渲染成新入榜。

趋势只收集当前相同口径的历史点，缺失日不填零、不合成排名。详情应展示实际日期。不能把两次不同口径指数的差异解释为歌曲真正变热或变冷。

上述变化写入 `combinedMovement`，与平台原榜的 `sourceMovement` 分开。后者表示平台相对自己的上期，汽水是上期周榜，不称作昨日；没有确认的排名编码保存在 `raw`，方向显示未知。MV 关联信息放在 `mv`，只记录平台提供的标识及已确认的官方链接。原榜涨跌和 MV 均不参与加权，补充这些元数据不会改变方法版本或得分。

## 7. 综合周榜

综合周榜按北京时间周一至周日，用同口径有效日分数的平均值计算。每个有效日从全部来源记录重建候选，避免日榜 Top 100 截断造成周榜漏项。缺失日不当作 0 分；有效日内歌曲没有正分才记 0。本周预览、缺日周和完整周明确区分，日期覆盖和平台覆盖分别披露，只有相邻完整且同口径的周才比较涨跌。完整规则见 [weekly.md](weekly.md)。

## 8. 后续可计算性

`data/runs/` 保留每轮规范化来源行，不是未经处理的原始 HTTP 响应。记录平台 ID、来源曲目 ID、名次、曲名、艺人、来源 URL、时间与期次，足够重算当前排名类指标；没有收集的平台播放量无法事后推算。

`npm run recompute` 使用已发布日榜内保留的来源行按时间顺序重建衍生榜。修改计分公式需提升版本；修改映射也会自动改变比较签名。历史重算不更改最初的观察档案。先积累真实日榜，再研究稳定性、平台重合度或趋势，不把缺少证据的指标塞进第一版。
