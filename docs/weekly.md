# 综合周榜 · weekly-1.1

周榜按北京时间周一至周日汇总已发布的日榜，不额外采集平台数据。每个自然日取最后一次有效快照，以本周最新日榜的模式和比较签名为基准，只纳入同口径日期。

## 计分

```text
周得分 = 同口径有效日得分之和 ÷ 有效天数
```

候选从各日完整来源记录重建，不受日榜已发布 Top 100 限制，日分遵循该日保存的[日榜方法](methodology.md)。v1.3 日榜中在有效期内沿用的 `stale` 来源与该日新采集的 `ok` 来源按同一权重计分；周榜不按今天的时间重新判断已发布历史观察是否过期。有效日中没有获得正分的歌曲记 0；缺失日和口径不同的排除日不进入分母。

v1.4 按该日保存的分平台窗口重建：四家 200、Apple 100、汽水 50，并使用保存的尾部分值曲线。第 101—200 名可以参与周分，页面展示前 100 名不截断候选；旧版日榜继续使用其原计分深度与曲线，不跨方法混算。

发布前 100 首；同分依次按获得正分的天数降序、稳定歌曲 ID 升序。`dailyScores` 列出有效日期的分数，`daysOnChart` 为获得正分的有效天数。

## 状态

| `status` | 含义 |
| --- | --- |
| `provisional` | 当前周预览 |
| `complete` | 已结束且七天均有同口径有效记录 |
| `incomplete` | 已结束但存在缺失或排除日期 |

`coverage` 披露有效天数、纳入日期、缺失日期、排除原因及来源覆盖。`observedDays` 是有效日分天数，不是独立新采集天数。`cachedDates` 列出使用过沿用来源的有效日；这些是发布日分的日期，不是新增的独立平台观察。日期完整不代表所有平台齐全或每日重新成功采集。`asOfDate` 为构建时的北京时间日期，`latestIncludedDate` 为最新有效记录日期。

## 涨跌与平台信息

只有相邻两周均为完整周，且模式、比较签名相同，才计算 `weeklyMovement`：上周名次减本周名次。可比较但上周无此曲时为新入榜，其余情况为未知。任一比较周含缓存日时 `coverage.comparisonUsesCache` 为 `true`。

每首歌的 `platforms` 保留本周有效日中各平台最近采用的名次、原榜涨跌、MV 关联和链接。`observedDate` 是 `fetchedAt` 对应的北京时间真实观察日；`includedDate` 是这份观察最近用于哪一天的日分，两者可能不同。沿用不会将 `observedDate/fetchedAt` 刷新成发布日，`status/ingestion/cacheOrigin/collectionError` 随平台记录保留。这是对应观察的原榜名次，不是周平均名次。

平台自身的周榜仍按原周期统计。独立平台历史回填不补作综合周榜的有效日。响应字段见 [API 文档](api.md)。
